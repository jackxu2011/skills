# 输出模板与示例

产出是一份 Markdown 文件，默认落 `docs/feature-spec/<页面名>.md`（项目已有文档目录约定则跟随，用户指定路径则用用户的）。文件名用页面标题，可中文。

**确认完才写这份文件。** 先按 [extraction-rules.md](extraction-rules.md#51-逐项与用户确认) 把待确认项逐项与用户过一遍，再落盘成文——不要先写一版带一堆问号的草稿再回来改。答了的直接进正文，用户明确跳过的才留到第 9 节。

**多张图只产一份文件**（除非它们确实是互不相干的页面）。文件头的「来源」里列清每张图是什么，正文用「图 1 / 图 2」标出信息出自哪张图——这是后续对齐冲突时的证据。

骨架章节固定，**图上有哪个区块就在第 5 节展开哪个**，没有的章节写「无」而不是删掉——删掉会让读的人分不清「这页没有」和「忘了写」。

## 完整示例

来源两张图 + 一段用户文字描述，**三者互不完全对应**：

- **图 1**：列表页，未打开浮层。统计区四项，卡片底部状态「已完成」，按钮「工作量评估」
- **图 2**：同一页 +「工作量评估」浮层。统计区三项，卡片底部状态「已确认」，按钮「工作量填写」
- **用户文字**：工作量评估是浮层录入「工作量 (人天)」；工作量不能为空，必须 > 0

> 本例的差异处理本身就是示范：图上有、文字没有的要提（附件、浮层关闭方式）；文字有、图上叫法不同的要对齐（`工作量(人天)` vs `工作量(天)`、功能描述 vs 详情内容）；**两张图对不上的地方两种口径都记**（统计项、按钮文案、状态名），成因一律进待确认的问法，正文只记事实差异。

## 4. 统计口径

## 5. 内容区

### 5.1 研发任务列表

- 形态：卡片流，纵向排列
- 排序：待确认（见 9.12）
- 分页：待确认（见 9.12）
- 空态 / 加载失败：待确认（见 9.12）

### 5.2 任务卡片

- **头部**：合同编号 + 合同名称（空格分隔，如 `25063 温州康居物业数据资产入表`），左侧有状态圆点
- **内容字段**：合同阶段、系统名称、功能模块、功能描述、任务类型、负责人、工作量、项目经理、计划完成时间、附件
  - 独占整行：合同阶段、系统名称、功能模块、功能描述
  - 一行两列并排：任务类型 | 项目经理、工作量 | 计划完成时间
  - **合同阶段**：阶段号 + 阶段内容，空格拼接（如 `2 项目阶段要求: ...`）；一行显示不下用 `...` 截断，**不换行**
  - **功能描述**：**完全显示**，允许换行
  - **附件**：`📎 文件名` 横向排布（图上有，用户文字描述未提及，见 9.11）

### 5.3 工作量评估浮层（图 2）

- **触发**：卡片底部右侧按钮（图 1「工作量评估」/ 图 2「工作量填写」，见 9.5）
- **形态**：居中浮层，带蒙层；标题「工作量评估」，右上角 `×` 关闭
- **字段与校验**：
  - `工作量(人天)`：数字输入框
    - **不能为空**
    - **必须 > 0**（用户书面说明）
    - 精度 / 上限 / 错误提示文案：待确认（见 9.7）
    - 界面文案单位：用户书面说明为「工作量(人天)」，图上 label 写作「工作量(天)」，以书面说明为准，差异见 9.4
    - 输入框内灰字 `100.00`：是占位提示还是回填当前值，待确认（见 9.7）
- **按钮**：`确定`（主按钮，提交）/ `取消`（描边，关闭不提交）
- **关闭方式**：`×` / `取消`；点击蒙层是否关闭，待确认（见 9.8）
