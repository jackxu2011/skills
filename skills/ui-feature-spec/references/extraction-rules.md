# 效果图提取规则

输入是页面视觉效果图（截图 / 设计稿 / 原型图，可能多张，可能附文字说明），产出是功能结构。按下面五步走。

---

## 1. 先定边界与图间关系

动手提取前先回答四件事，写进规格的「页面概述」：

| 要定的 | 从图上怎么认 | 认不出怎么办 |
|---|---|---|
| **页面名称** | 顶部导航栏 / 标题栏文字（如「产研计划」） | 看浏览器标签或用户给的说明；都没有 → 待确认 |
| **页面形态** | 有底部 tab / 返回箭头 + 顶栏 = 移动端 H5 或小程序；有侧边栏 / 大面积表格 = PC 后台；弹层覆盖 = 弹窗而非页面 | 影响字段密度与操作布局，必须定下来，定不下 → 待确认 |
| **页面用途** | 标题 + 主要内容区的性质（列表 / 详情 / 表单 / 看板） | 一句话概述写不出就说明还没看懂图，继续看 |
| **入口与返回** | 顶栏的返回 / 关闭 / 面包屑 | 图上没有 → 待确认 |

**多张图默认属于同一个功能**（主页面 + 浮层 + 二级页 + 不同状态），目标是抽出**一份完整功能**，不是一图一份。只有确实是互不相干的页面（两个独立页面、两个模块）才分多份。

| 图间关系 | 判定依据 | 处理方式 |
|---|---|---|
| 主页面 + 浮层 / 弹窗 | 一张图上有蒙层覆盖的卡片 | 合并；浮层单列一节，写清**触发它的操作**与**关闭后的联动** |
| 同页的不同状态 | 主体结构一致，只有标记 / 按钮 / 统计数字不同 | 合并；差异进「状态与分支」 |
| 同一流程的先后两屏 | 一屏是点击前、一屏是点击后 | 合并；串成一条操作链路 |
| 不同页面 | 结构不同、入口不同 | 分多份规格 |

**合并时必须对齐，不许挑一张当准**：

1. **先串交互链路**：图与图靠操作串起来（点「工作量评估」→ 弹层 → 确定 → 列表刷新），链路写进「操作」表
2. **对齐同名字段**：同一字段在不同图里文案、单位、格式可能不同（如 `工作量(天)` vs `工作量(人天)`），以用户书面说明为准，差异列待确认
3. **对齐全局区块**：统计项、按钮文案、状态名对不上时（一张写「已完成」另一张写「已确认」），**两种口径都记下来**列待确认——不许合并成一个，也不许只留一张图的
4. **状态差异只记录、不解释**：两张图标记不同（一张「已完成」、一张「已确认」），**成因图上看不出**。正文只写事实差异 + 待确认编号；「是不是填完工作量后变成已确认」这类解释只能写进待确认的**问法**里

**分清标注与内容**：图上的虚线框、箭头、圈注、红字说明、尺寸标注，是设计给开发的注解，不是页面元素。看到这类标注时它往往就是关键信息（它在强调某个规则），但要转成规则写进正文，不要当成一个界面区块。

## 2. 划功能区块

从上到下扫一遍，切出功能区块。区块的判定依据是**视觉分组线索**：圆角卡片边界、分割线、留白、底色差异、对齐关系。

常见区块（按出现频率排，图上有哪个提哪个，没有的不硬造）：

| 区块 | 视觉线索 | 提取什么 |
|---|---|---|
| **查询区** | 搜索框、放大镜图标、placeholder 文案 | 一个条件还是多个条件、每个条件过滤哪些字段、多字段之间用 OR、与其它条件用 AND |
| **筛选区** | 日期选择器、下拉、标签页、chips | 筛选项、值域（到月 / 到日 / 到年）、默认值、筛选作用于哪个字段（如「计划完成时间」而不是泛泛的「时间」） |
| **统计区** | 数字 + 单位的并排数字组、看板卡片 | 统计项、每个统计项的口径、维度（个数 / 工时 / 金额）、与下方列表的筛选关系 |
| **内容区（列表 / 卡片流）** | 重复的行或卡片 | 列表形态（表格行 / 卡片）、排序、分页或滚动加载、空态 |
| **列表项内部** | 单个卡片 / 行内部的字段组 | 头部 / 内容 / 底部三个子区，字段与显示规则 |
| **操作区** | 按钮、图标、操作列 | 操作项、操作的前置条件（什么状态下才出现）、是否需要二次确认 |
| **状态标记** | 绿色/灰色标签、角标、勾 | 状态取值、状态如何改变版式 |
| **弹层 / 抽屉** | 蒙层 + 浮起卡片 | 标题、触发它的操作、表单字段与校验（必填 / 范围 / 精度）、按钮与关闭方式（确定 / 取消 / 右上 × / 蒙层点击）、提交后的联动 |

**层级与从属要写出来**：一行两列并排 = 同级并列；缩进 / 小字 = 从属。例如卡片里「任务类型」和「项目经理」并排一行，是同级字段；「合同阶段」缩进在标题下，是从属于卡片头的字段。

## 3. 抠字段与显示规则

每个字段按这五项提，缺哪项就标待确认：

```
| 界面文案 | 业务字段名 | 取值来源/示例 | 显示规则 | 备注 |
```

- **界面文案** = 图上 label 的原文（`工作量/天`、`计划完成时间`）
- **业务字段名** = 给前后端对齐用的字段名（`workload`、`planFinishTime`），与文案不一致时以字段名为准，备注里注明界面文案
- **显示规则**必须写到能实现，至少覆盖这四种情况：

| 情况 | 写法示例 |
|---|---|
| 超长 | 「一行显示不下用 `...` 截断，不换行」/「完整显示，允许换行」 |
| 格式 | 「`yyyy-MM-dd`」/「`2026.09`（只到月）」/「金额保留 2 位小数」 |
| 空值 | 「为空显示 `-`」/「为空不显示该行」/「为空显示占位文案」 |
| 拼接 | 「阶段号 + 阶段内容，空格拼接」/「多值用 `、` 分隔」 |

**图上最容易被漏掉的两类信息**：

1. **截断与换行**：同一张图里有的字段换行了、有的被 `...` 截断了，这个差异本身就是规则。例：卡片里「合同阶段」截断到两行、而「功能描述」完全显示——要显式写出来。
2. **数值的单位与精度**：`工作量/天: 15.00` 说明工作量是两位小数的数值；`计划完成时间: 2026.09` 说明时间只到月。格式不是随手写的，按图上实际显示反推。

**操作按链路提，不是按钮清单**。静态图只画得出前两段，后五段要么从多张图串出来，要么列待确认：

| # | 链路段 | 提取什么 | 图上能看到吗 |
|---|---|---|---|
| 1 | 触发入口 | 哪个按钮 / 图标 / 行点击、按钮文案 | 能 |
| 2 | 打开的界面 | 浮层 / 新页 / 就地编辑；标题、关闭方式（× / 取消 / 蒙层点击） | 多图时能 |
| 3 | 输入项与校验 | 每个输入项的 label、单位、格式、精度、必填、取值范围、错误提示 | 看不出（只有输入框） |
| 4 | 提交动作 | 确定 / 取消文案、取消是否二次确认、提交中态 | 部分 |
| 5 | 反馈 | 成功 / 失败提示、浮层是否自动关闭 | 看不出 |
| 6 | 数据与状态联动 | 列表是否刷新、统计是否重算、卡片字段是否更新、**状态是否改变** | 看不出 |
| 7 | 可重复性与权限 | 提交后能否再改、谁可以操作 | 看不出 |

> **3–7 段图上一律看不出**：用户说了就写并标「用户说明」，没说就整段写「待确认」。不要用「一般会自动刷新」这类常识去填。

**卡片 / 列表项按「头—内容—操作」三段提**，这是最常见的形态：

- 头部：标识信息（编号 + 名称）、状态点 / 标签
- 内容：字段组，注意哪些一行两列、哪些独占整行、哪些可能截断
- 底部：状态标记 + 操作按钮，两者的位置关系（状态在左、操作在右）要写

## 4. 图上看不见的：登记，不补

效果图只画了「一次成功加载后的样子」。下面这些它永远画不出来——**不要补**。处理办法只有两条路：

1. **用户明确说过的**（含当场回答你提问得来的）→ 照写，标「用户说明」/「用户确认」
2. **用户没说的** → 登记进「待确认项」，配一句能直接问出口的话

**正文里留白是正确产出**，不是没做完。「数据权限：待确认（9.1）」远比编一句「按负责人过滤」有价值。也不许拿「同类页面一般怎么做」「后端通常怎么设计」去填——那不是提取，是编造。

**数据权限**——谁能看见这些数据。**图上取不到**：效果图只画了某个用户看到的一屏，看不出这份数据是恰好归他，还是所有人可见。

- 用户说了（例：「任务负责人为本人或下属的研发任务」）→ 照写，标「用户说明」
- 用户没说 → **整节留空**，写「待确认」并给问法

「按负责人 / 按组织 / 按角色 / 按项目归属」这些常见口径**只准出现在问法里**帮对方想，不许写进正文当结论。这一节永远不许省，也不许因为图上没画就默认所有人可见。

**查询与筛选的作用范围**——图上最多给出提示（搜索框 placeholder 列了两个字段名），**字段之间是 OR 还是 AND、和统计是不是同一套过滤，图上定不了**。用户说了（例：「同一个查询条件，同时过滤两个字段，用 OR 连接」）就照写并标「用户说明」；没说就待确认。

**统计口径**——图上只看得见**统计项名称 + 数字 + 单位**，口径（统计对象、维度、时间范围、与筛选的关系）一律看不出。用户说了就写，没说逐项待确认。

**分清观察与推断**：「图上任务数 12 个，但三项之和是 18 个」「一处写天、一处写人天」是**观察**，可以写进正文；「为什么会这样」「是不是笔误」是**推断**，只能进待确认的问法。

**相互矛盾的内容记下来，最后统一确认**——图与图、图与文字对不上时，两种口径都记进待确认项，不静默择一。**只有矛盾卡住抽取进行时才当场问**（认不出这是哪一页、几张图关系不明）。

**状态分支**——图上看得见的只有**标记长什么样、在哪个位置、什么颜色**；**判定条件**（什么算已完成、什么算已关闭）和**状态取值全集**都看不出。

- 标记样式与位置：照图写（如「在操作列左侧显示 `已完成 (yyyy-MM-dd)`」）
- 判定条件、状态全集、各状态可用操作：登记进待确认项（见下方「枚举型字段」），留到最后统一确认
- 两张图标记不同时（一张「已完成」、一张「已确认」），**只记差异，不解释成因**

**枚举型字段**——`xx 状态`、任务类型、分类这类有限取值的字段，图上只画得出碰巧出现的那几个，**取值全集一律取不到**。把图上见到的取值记下来，连同每个取值的判定条件与版式差异（颜色、标记、可用操作）一起**登记进待确认项，留到 5.1 统一确认**，不打断抽取。

**表单校验**——图上只画得出一个输入框，**必填性、取值范围、格式、精度、错误提示文案一律看不出**。用户给了（如「工作量不能为空，必须 > 0」）就照写并标「用户说明」，没给就列待确认。

**操作链路的后五段**——输入校验、提交、反馈、数据与状态联动、可重复性（见第 3 节的链路表）。这几段图上全看不出，**不许猜「提交后会自动刷新」**；用户说了照写，没说整段待确认。

**操作行为**——图上只有一个静态按钮时，点下去发生什么（跳转 / 弹窗 / 就地编辑 / 二次确认）待确认；第二张图画出了弹层，才补上「打开的界面」这一段。

**空态 / 加载 / 异常态**——图上画的永远是「加载成功后」，这三态一律待确认。

**分页与排序**——一次全量 / 分页 / 滚动加载、默认排序字段与方向，图上看不出，待确认。

## 5. 图上看不出的信息：标准问法

第 4 步补不出来的，落进「待确认项」表，每条配一句能直接问出口的话。

| 主题 | 问法示例 |
|---|---|
| 数据权限 | 「这个列表的数据范围是「本人负责」还是「本人及下属负责」？下属的定义是按组织架构还是按汇报关系？」 |
| 查询条件 | 「搜索框一个关键字同时匹配合同编号和合同名称，是这样吗？还有别的字段要一起匹配吗？」 |
| 筛选作用 | 「选择的月份是按哪个时间字段过滤？计划完成时间还是实际完成时间？」 |
| 统计口径 | 「这四个统计数字是按当前筛选结果算的，还是不受筛选影响的全量？工作量的单位是「人天」吗？」 |
| 枚举取值 | 「「任务状态」除了图上看到的这两个，还有哪些取值？每个取值怎么判定、按钮有什么不同？」 |
| 状态流转 | 「什么条件下任务进入「已完成」？「已关闭」是人工关闭还是超期自动关闭？」 |
| 操作行为 | 「「工作量评估」点开是弹窗填写还是跳转到新页面？点蒙层或 × 能直接关吗？」 |
| 校验规则 | 「工作量允许填 0 吗？最多几位小数？填错时提示文案是什么？」 |
| 联动刷新 | 「确定之后列表和顶部统计会立刻刷新吗？任务状态会变成「已确认」吗？」 |
| 可重复性 | 「已经填过工作量的任务还能再改吗？谁有权限改？」 |
| 空态异常 | 「没有数据时显示空态插图还是仅一行提示？加载失败要重试按钮吗？」 |
| 分页 | 「任务多时是分页还是下拉加载？默认按什么排序？」 |
| 权限控制 | 「这个操作按钮对所有人都可点吗？有没有角色限制？」 |
| 富内容 | 「附件支持哪些类型？能预览吗？能删除吗？谁上传的谁能删？」 |
| 数字矛盾 | 「图上任务数 12 个，但已完成 12 + 未完成 6 + 已关闭 0 = 18 个，这几个口径分别是什么？」 |

**待确认项的写法**：`| # | 待确认 | 影响 | 建议问法 |`，「影响」写清不确认会卡住什么（阻塞接口设计 / 阻塞页面开发 / 只影响文案），方便排优先级。

### 5.1 逐项与用户确认

待确认项**收集完之后**，统一与用户逐项过一遍，**过完才写最终文档**。不要抽取到一半零星地问，也不要带着一堆问号直接出稿。

1. **排序**：按「影响」排——阻塞接口设计 / 阻塞页面开发的先问，只影响文案的最后问
2. **分批**：用 `AskUserQuestion` 每批 3–4 项，每项给 2–4 个候选答案（用户选「Other」可自由作答）。**候选答案只能来自图与用户已给的信息**，不许塞你猜的进去当选项
3. **记答案**：用户答了 → 按答案改正文、标「用户确认」，并从清单划掉
4. **收尾**：用户明确说「跳过」「先这样」的 → 留在最终文档第 9 节；问完仍不确定的同理

**当场确认只用于「卡住抽取」的问题**，判定标准见 SKILL.md 硬约束；**其余一律进清单留到最后**，抽完一起过。抽取过程中当场问掉的，直接从清单划掉。
